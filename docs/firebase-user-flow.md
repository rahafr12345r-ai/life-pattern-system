# تدفق المستخدم والموافقة

## إنشاء الحساب

عند إنشاء الحساب بالبريد أو Google، يُنشأ مستند داخل مجموعة `users` باستخدام UID القادم من Firebase Authentication. يحفظ المستند البريد الإلكتروني، الدور المختار (`Patient` أو `Doctor`)، وحالة الموافقة، وتاريخ الإنشاء.

## تسجيل الدخول

بعد نجاح Firebase Authentication، تراقب `AuthGate` حالة الحساب. إذا لم يوجد ملف مستخدم أو لم تُقبل الموافقة، تظهر شاشة الخصوصية والموافقة. بعد القبول، تُقرأ قيمة الدور ويُفتح مسار Patient أو Doctor.

عند تسجيل الدخول بواسطة Google من شاشة Sign in مباشرة، يُنشأ الملف بدور Patient افتراضي. أما مسار Create account فيسمح باختيار Patient أو Doctor قبل إنشاء الملف.

## الموافقة

لا يسمح التطبيق بالوصول إلى صفحات النظام قبل حفظ `consentAccepted: true` في Firestore. النص يوضح أن النظام يقدم مؤشرات سلوكية مبكرة وليس تشخيصًا طبيًا، وأن مشاركة البيانات مع المعالج تتطلب موافقة المستخدم.

## ملاحظات المرحلة

الواجهات الحالية لـ Patient وDoctor هي نقاط دخول مؤقتة لتثبيت التدفق. سيتم استبدالها بشاشات Home وPatients المطابقة لـ Figma في خطوات الواجهة التالية.
