# بنية المشروع ومسؤوليات الوحدات

## mobile_app

`mobile_app` هو تطبيق Flutter الرسمي. مجلد `lib/features` سيحتوي الوحدات الوظيفية المنفصلة: المصادقة، الإعداد الأولي، لوحة المستخدم، البيانات السلوكية، خط الأساس، تحليل المخاطر، التنبيهات، التقارير، الملف الشخصي والخصوصية. أما `core` و`config` و`constants` و`shared` فتحتوي ما هو مشترك بين الوحدات، بينما تتولى `services` و`repositories` و`providers` الاتصال بالخدمات وإدارة الحالة وفق القرار الذي سيُعتمد في مرحلة الواجهات.

## backend

`backend` هو خادم Python/FastAPI. ستنفصل المسارات عن الخدمات والمستودعات والنماذج ومخططات الإدخال والإخراج. سيكون `analysis` وحدة مستقلة لمحرك خط الأساس واكتشاف الشذوذ، حتى يمكن اختباره دون الاعتماد على واجهة Flutter.

## docs

يحتوي `docs` على متطلبات النظام، المعمارية، عقود API، تصميم قاعدة البيانات، استراتيجية الاختبار، وجرد Figma. هذه الملفات توثق القرارات قبل تنفيذها وتمنع تغيير متطلبات التقرير أثناء البرمجة.

## حدود المرحلة الأولى

المرحلة الحالية أنشأت الهيكل وملفات البداية فقط. لم تُنشأ بعد مصادقة Firebase أو مجموعات Firestore أو مسارات API الخاصة بالمنتج أو قواعد التحليل أو شاشات Figma الوظيفية.
